Part 1Foundations#

1.1 Principles#

Status: Live

Make Octran understandable at a glance, then give each product enough room to explain how it works. The site should feel deliberate and capable, not like an operations dashboard or a wall of decorative cards.

  • Clear first, detailed when useful. Editorial scale and open rows carry the hierarchy.
  • One signal. Orange marks the current action or relationship. Nothing else is orange.
  • Show the mechanism. Illustrations explain how the work moves. They never decorate or imply a live deployment.
  • Honest by default. Facts are verifiable, examples are labelled illustrative and unknowns are named (Part 6).

1.4 Layout and grid#

Status: Live (rail, gutters, rhythm) · Proposed (visible grid, panels)

  • Rail: 1680px maximum (the proposed sections use a 1312px container). Gutters: 20px mobile, 32px tablet, 48px desktop, 64px wide.
  • Header: 32px orange investor strip above a sticky graphite bar, 72px desktop and 64px mobile. The app measures the combined height for anchor offsets.
  • Rhythm: section padding clamp(64px, 8vw, 120px). Use open rows and 1px rules, not boxed paragraphs.
  • Product declarations: asymmetric two columns, a large name on the left and a plain-language purpose on the right.
  • Small screens: one column in reading order. At 320px width and 200% zoom, no page-wide horizontal scroll.

Visible grid (proposed, adapted from peregrine.io):

ElementSpec
Column rules12 faint rules across dark sections, slate at 14% (--grid-rule)
Signal nodes6px orange squares where a rule meets a section boundary; at most 4 per boundary, only on the outer and centre rules
Dot grid16px spacing, slate at 22% (--dot-grid); behind diagrams and context maps only
BehaviourDecoration only (aria-hidden). Text never sits on a rule. Under 768px only the boundary line remains.

Panels (proposed, adapted from foundry.helix-db.com): on product pages, a section can be a 1px #2A2A2F box with a 20–32px gap between boxes. Split panels divide into equal cells with internal rules and a bottom caption row (01 Context). See K14.

1.5 Geometry and iconography#

Status: Live

  • Square corners everywhere: radius 0, no card system, no offset shadows, no raised controls.
  • Boundaries are 1px rules. Focus outlines are 2px and offset 4px from the control.
  • Icons are 1.5px-stroke line icons. No emoji.
  • Minimum target 44px; controls 48px tall.

Part 3Motion#

3.1 Principles#

Status: Live (rules) · Proposed (anime.js system)

  • Motion explains the system or gives immediate feedback. It is never decoration.
  • Never: marquees, scroll traps, required reveal animations, automatic workflow rotation.
  • Scroll-linked scenes are allowed only when: the page scrolls natively, all content reads without the animation, and every state is reachable by keyboard.
  • One signal moves at a time. Idle loops stay small (bars, nodes, a gem spin). Docking, signals and stamps happen only on scroll or a click.
  • Respect prefers-reduced-motion in CSS and JavaScript (3.4).

4.2 Rendering#

Status: Proposed · reference implementation: the live lab (Appendix C, style-guide/lab.js)

StepSpec
CameraOrthographic, true isometric from (1,1,1), looking at the model centre
Pass 1: encodeEach part writes a unique ID colour mixed 25% with its faceted view normal (from screen-space derivatives) into RGB, and a signal flag into A (0.8 signal, 0.5 other)
Pass 2: linesSample 4 diagonal neighbours. Colour jump ≥ 0.14 → line (smoothstep to 0.22 for anti-aliasing). Part seams always draw; creases draw above ~33°, so cylinders show silhouettes, not facets. Line colour is --bp-line, or --bp-signal where a signal part touches the edge. Part interiors are painted --bp-ground; empty pixels stay transparent.
FloorGrid helper lines in --bp-construct at 16%, drawn before the line pass, so parts hide them
SVG mockupsThe same rules as a CSS layer: face fills → ground, ink strokes → line, signal solids → orange outlines (the scoped "blueprint layer" rules in style-guide/mockups.css)

4.4 Callouts and labels#

Status: Proposed

  • JetBrains Mono 11px with +6% tracking. Apricot title line (02 / CORTEX), slate role line (UNDERSTANDING).

  • Callouts are HTML positioned over the canvas, recomputed each frame from projected anchors, and fade with their scene.
  • Hide them under 768px. The chapter caption carries the same information.

4.5 Live canvas model#

Status: Live (home and investors)

The current site uses a 2D-canvas orthographic blueprint model (components/site/BlueprintModel.tsx): graphite or paper planes, crisp neutral outlines, sparse construction marks and one orange trace.

  • 32s full orbit with damped manual rotation.
  • Controls: Pause/Play, Reset, a keyboard-operable angle range and a labels switch.
  • Reduced motion starts static.
  • A static SVG fallback and a text description are always present.

Part 4.1–4.4 is its successor.

2. The 3D look — "ink outline toon"#

The models are not lit realistically. It is a two-pass non-photoreal (NPR) pipeline:

Pass 1 — encoded material (outlineMaterial, a MeshLambertMaterial-style material patched with onBeforeCompile):

  • RGB = the mesh's vertex colour (used as a part ID: pure black/red/green/blue/pink/yellow/cyan are reserved IDs) mixed with a little view-space normal colour (verticesNormalMix 0.08, faded by depth). Different parts and different face angles therefore produce different colours.
  • Alpha = a light mask: 1 where lit, ~0 in shadow, minus a rim term rimDot = 1 − dot(viewDir, normal) × pow(NdotL, rimThreshold).

Pass 2 — full-screen outline shader (custom, ~40 lines):

  • Samples the encoded buffer at 4 diagonal offsets (outlineThickness 1) and takes the colour-difference magnitude; edge > threshold (0.035) → ink line. Because part IDs and normals differ, this finds silhouettes, creases and part seams in one test.
  • Repaints every pixel from a CSS-variable palette: background (pure white input → --backgroundColor), paint (--worldColor1 #423d3d), lit-rim tint (--rimColor #ffc7a8, warm apricot) where alpha ≥ 0.95, shadow (--shadowColor #212121) where alpha ≤ 0.3, line (--outlineColor #101010, blended 40 % toward paint).
  • Rendered at resolutionScale 4 for the edge sampling, then FXAA. antialias:false, pixelRatio 1, no depth/stencil buffers on the default framebuffer.

Result: flat graphite solids, crisp dark contour lines, a warm rim on lit edges, a two-tone shadow band. It reads like a technical illustration that moves. Colours come from CSS, so a section's theme recolours the 3D.

Modelling conventions observed: chunky low-poly mechanical parts; hard bevels; vertex colours instead of textures; small sub-parts (pins, teeth, springs) that are animated individually; an exploded-assembly layout where each feature is one "module" of a larger engine (engine scale 10, camera FOV 40, lookAt(scene.position)).

The eight concepts#

  1. Octagon Core: home hero. Tako, Octran's AI, is "octopus" in Japanese and Octran begins with "oct". The hero is an exploded octagonal core with eight arms. As the visitor scrolls, the three foundations dock into it: Tele (signal drum), Cortex (lattice block) and Ledger (tape spool). The orange signal then runs arm → core → arm. Headline: "Keep the context. Move the work." The last word scrambles through order · invoice · reply · handover · work using scrambleText({ chars: 'blocks' }).
  2. Context Assembly Line: Nexus page spine. A scroll-synced master timeline (onScroll({ sync: .7 }), the value tuned in the lab) moves one packet (the customer question) along a rail through five stations: Tele → Cortex → Tako → Gate → Ledger. Each station has a numbered callout pinned by a leader line. This makes the existing delayed-order workflow physical.
  3. Cortex Lattice. A 7×7 grid of instanced nodes. Selecting a record (the customer) sends a ripple out from that cell (stagger(40, { grid: [7,7], from: index })). Related nodes rise and turn orange, and each one is joined to a source label ("Contract", "Order #—", "Earlier call").
  4. Tele Signal Drum. A horizontal drum of 48 waveform bars. Bar heights are scaled by stagger from the centre, and transcript lines scramble in beside it. The drum stops rotating when the conversation is linked to its customer card, the "context locked" beat.
  5. Ledger Tape & Stamp. A seven-segment entry counter ticks up while a paper tape prints entries line by line. A stamp press comes down with out(4) and marks the result: APPROVED · NOT SENT · OPEN. Recording failures and open work is part of the brand promise.

Changed plates slide out with their changed bands lit orange, and a review tick seals each one. These are abstract plates, not fake UI; real JevCode screenshots stay on the product page as the brand guide requires.

How a page is rendered#

  • Every route is a thin wrapper. For example app/about/page.tsx renders <ArchivePage file="about.html" />.
  • components/archive/ArchivePage.tsx reads the matching file in site-pages/ at request or build time. It pulls the <title> and meta description from that file for SEO, then passes the <body> on to PublicPages.
  • components/site/PublicPages.tsx chooses what to show based on the file name:
    • Marketing pages (Home, Nexus, Modules, JevCode, About, Investors, Pricing and the rest) are hardcoded React in this one file. Their copy lives in the component, not in the HTML file.
    • Blog posts and the privacy, terms and security pages use ReadingPage. It takes the <article class="prose"> content from the HTML with regexes and rewrites the .html links to clean routes.
    • The blog index is built by scanning site-pages/blog.html for post links.
  • Blog posts are pre-built at build time from site-pages/blog/*.html and are all marked noindex.
  • Other routing pieces: next.config.js permanently redirects old *.html URLs to the clean routes; app/sitemap.ts and robots.ts cover search engines; each route has an opengraph-image.tsx that draws its share image through lib/og-image.tsx.

Design in code#

  • One stylesheet. All styling is in app/site.css, a single minified file of plain CSS classes. Tailwind is still installed, but these components do not use it.
  • Tokens as CSS variables. Colours (ink #131315, white, soft grey, orange #FF5E1A and deep #b9480f), fonts and the 1680px rail are variables on :root. Inter is the text face and Newsreader the serif accent, both loaded locally in app/layout.tsx.
  • Look. Square corners, thin divider lines, large headings, dark sections alternating with light ones.
  • Shared shell. The layout wraps every page in SiteHeader (announcement bar, <details> dropdown menus, a mobile menu, and it tracks its own height for the sticky offset), SiteFooter (link directory) and TimedLeadCapture (the early-access popup).
  • Building blocks in components/site/UI.tsx: Action, TextLink, ProductDeclaration, EditorialOpening, Closing and SystemDiagram, an isometric SVG diagram.

Backend#

  • app/api/lead-capture/route.ts handles POST from the popup.   • The contact page form (ContactForm) posts nowhere. It opens a pre-filled mailto:hello@octran.tech email.
  • There is no content database and no authentication.
